# 架构与数据流

## 总体结构

```
                     ┌─────────────────┐
                     │  人物参考图 PNG  │
                     └────────┬────────┘
                              │
                     ┌────────▼────────┐
                     │  LRC 歌词文件    │
                     │  (句起点时间轴)  │
                     └────────┬────────┘
                              │
                     ┌────────▼────────┐
                     │  plan.py         │  按句子边界切段
                     │  切分器          │  每段 ≤ 260 帧
                     └────────┬────────┘
                              │  plan.json
                     ┌────────▼────────┐
                     │  gen.py          │  逐段循环
                     │  生成器          │  ┌─ 提交 ComfyUI
                     └────────┬────────┘  ├─ 等完成
                              │            ├─ whisper 校验
                              │            ├─ 合格 → 抽末帧
                              │            └─ 不合格 → 换种子重试
                              │
                     ┌────────▼────────┐
                     │  shots/          │  已通过的段
                     │  shot_000.mp4    │
                     │  shot_001.mp4    │
                     └────────┬────────┘
                              │
                     ┌────────▼────────┐
                     │  ffmpeg concat   │  顺序拼接
                     └────────┬────────┘
                              │
                     ┌────────▼────────┐
                     │  成片 mp4        │
                     └─────────────────┘
```

## 为什么是"逐段独立提交"而不是节点内循环

MiniMax H3 提供两种长视频方案：

| 方案 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| **节点内循环** | 单一 ComfyUI 任务，内部自动分段，段间用 `cosine_bridge` 在 latent 层续接 | 快、亮度连续 | **不能中途介入**，一段失败要整条重跑 |
| **逐段独立提交**（本项目） | 每段一个 ComfyUI 任务，上一段末帧作下一段首帧 | **可校验、可重试、可断点续跑** | 慢一点，需要自己管链条 |

**选后者的理由**：模型会改词、会自编内容、会念水印。**没有校验的自动化等于批量生产废片。**

## 单段的请求结构

每段向 ComfyUI 提交的图（简化）：

```
UNETLoader ──→ LowVRAMAttention ──→ ChunkFeedForward ──┐
                                                       │
CLIPLoader ────────────────────────────────────────────┤
                                                       ▼
VAELoader(video) ────────────────────────→ LongVideoLoop
VAELoader(audio) ──────────────────────────┘        ▲
                                                     │
LoadImage(first_frame) ──────────────────────────────┤
                                                     │
PromptRelayPlan ──→ QueryRoute ──────────────────────┘
       ▲
       │  全局 prompt（人设/音色/场景）
       │  时间轴 prompt（台词或动作描述）
       │  帧数 + 帧区间
```

**关键输入**：

| 输入 | 作用 |
|---|---|
| `first_frame` | 本段第一帧必须是什么（第 1 段用原图，之后用上段末帧） |
| `persistent_identity_image` | 持续把画面拉回原图的身份约束 |
| `prompt_relay_plan` | 台词与时间轴的绑定 |
| `chain_id` | 本段唯一标识，**每次改配置必须换新** |
| `render_window_frames` | 必须在 17n+5 网格，最小 124，最大 260 |

## 校验环路

```
生成完成
   │
   ├─ 唱段 ──→ whisper 转写 ──→ 拼音相似度 ≥ 0.85 ?
   │                              ├─ 是 → 通过
   │                              └─ 否 → 换种子重试（最多 3 次）
   │
   └─ 间奏段 ─→ whisper 转写 ──→ 字数 ≤ 6 且不含水印词且为纯气声 ?
                                  ├─ 是 → 通过
                                  └─ 否 → 重试（最多 3 次）→ 静帧兜底
```

**为什么用拼音而不是字符**：whisper 对唱歌输出繁体与同音错字，字符级相似度会把正确的生成判成失败（实测 0.714 vs 拼音 0.990）。

## 状态管理

`state.json`：

```json
{
  "done": { "0": "shots/shot_000.mp4", "1": "shots/shot_001.mp4" },
  "prev_frame": "shots/shot_001_last.png",
  "bad": [4],
  "static": [1, 12, 22]
}
```

- **`done`**：已通过的段（重启时跳过）
- **`prev_frame`**：下一段要用的首帧
- **`bad`**：降级通过的段（质量存疑）
- **`static`**：用静帧兜底的间奏段

## 时间轴切分策略

**输入**：LRC 歌词（每句起点时间）

**规则**：

1. 每段从某句起点开始
2. 累加后面的句子，直到接近但不超过 260 帧（10.83 秒）
3. **10.83 秒是上限，不是下限**——一句只有 7 秒就生成 7 秒的段
4. 句间空白 > 5 秒判定为间奏段
5. 帧数吸附到 17n+5 网格，且不低于 124

**为什么以句子边界切**：切在句子中间会导致"上一段半句结束、下一段半句开始"，观感断裂。

|---|---|
| 显卡 | RTX 5070 Ti 16 GB |
